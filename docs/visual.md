# sitegarden — visual direction

Look and procedural generation for the garden theme (`@sitegarden/theme-garden`). The core knows nothing about this; it is one theme plugin. See plan.md for the plugin system.

## Visual direction

Cartography meets orchard: an estate garden plan, not a fantasy map.

- **References:** [felt.com](https://felt.com) (warm paper, faded grey contour lines, muted colour), [maggieappleton.com](https://maggieappleton.com) (hand-drawn outlines, serif headings, personal feel), Middle-earth interactive map for lettered place labels only (no burnt parchment, no gothic type).
- **Metaphor:** a project = a fenced plot (hedge outline); its repo, CMS and site = trees/buildings inside it; connections = dashed paths; a running deploy = ink moving along the path; contour lines = background texture only.
- **Look:** watercolour illustration (Felt-style): painted terrain, tree clusters, roads and buildings that dissolve into blank paper at the edges; crisp modern UI floats on top (white cards, Fraunces for headings and map labels, Outfit for text, JetBrains Mono eyebrows). Not hand-lettered or cartoonish.
- **Paper:** flat handmade paper, no 3D relief: warm off-white with random specks, small inclusions and short coloured fibres.
- **Two intensities:** project plots are muted Felt-like watercolour (sage, ochre, blue-green) with pooled pigment edges, granulation, small unpainted paper holes, drops and drips at ragged borders; everything else (neighbourhood, streets, background trees) is greyed out and fades softly into the paper, with no outline. No river.
- **Plot names:** Outfit semibold, spaced capitals (cartographic style), not serif.
- **Text smears:** the side menu and every map label sit on a soft, irregular smear of paper colour (no hard edges): fully opaque behind the text, fading out toward its edges, so specks and stars never show behind letters but creep back in around them. In the product the smears are generated around each label's bounding box and baked into the map bitmap.
- **Night theme:** same map, ink-blue sky paper; paper specks become small yellowish stars (a few twinkle). Lights carry status: healthy buildings have lit windows and greenhouses glow, a down site goes dark, a deploy is a lantern travelling along its road. Street lamps on roads, one seeded campfire per plot (flickers). Optional "night sounds" toggle (crickets), off by default.

## Procedural generation

Everything visual is derived from seeds, so the map is identical on every reload and every device.

- **Seeds:** each account gets a random `accountSeed` stored server-side at creation. Every element uses `hash(accountSeed, entityId, purpose)` → seeded PRNG (mulberry32 or sfc32). Hashing per ID means adding or removing one project never changes the others.
- **Plot shape (no fixed templates):** target area = base + per-building area × count × random(0.85–1.3). Shape = closed blob from a polar outline whose radius is modulated by 1D simplex noise around the circle, random aspect (0.7–1.4) and rotation, smoothed with Catmull-Rom. Watercolour filter params (edge pooling, holes, drips) are also seeded per plot.
- **Building slots:** Poisson-disk sampling (Bridson) inside the shape, min distance from building footprints. Buildings are assigned along the plot's main axis in data-flow order (studio → repo → site), so roads read left to right.
- **Roads:** each connection is a seeded curve between its buildings; extra garden paths come from a minimum spanning tree over the slots plus a few random extra edges.
- **Garden style per plot:** seed picks a biome (orchard rows, meadow, vineyard stripes, pond garden, rock garden), which weights the Poisson scatter of trees, beds, rows and ponds.
- **Buildings:** type → family of variants. Studio = greenhouse / conservatory / glasshouse; repo = warehouse / barn / workshop; site = house / cottage / villa; database = silo / well; worker = mill / windmill; unknown = shed. Seed picks variant, footprint size, roof shape (gable, hip, flat), annexes (0–2), chimneys, and roof and wall colours from a curated muted palette (terracotta, slate, sage, ochre, plaster).
- **World layout:** plots are placed in creation order on a spiral around the origin with collision avoidance (seeded jitter in angle and distance). Positions are saved once computed, so new projects grow the map outward and nothing jumps. Dragging a plot overrides and saves its position.
- **Neighbourhood:** a simplex-noise density field decides what goes where: town districts (street grid with a seeded rotation per district, houses along streets), fields (stripes), woods (dense trees), empty paper. Plots plus a margin are kept clear. Generated in tiles, rendered once to bitmaps (OffscreenCanvas) and cached (IndexedDB in the browser, also on the server); a tile is only regenerated when something near it changes.
- **Paper specks and night stars:** generated by our own code, not browser filters. A low-frequency simplex-noise density field decides *where* (clusters and empty patches); Poisson-disk sampling with radius scaled by that density decides *exact positions* (no clumps on top of each other, no grid look); size and opacity come from a power-law distribution (many tiny, few large). Light theme: brown specks plus a few coloured fibres. Night theme: same points, far sparser, as warm stars (a handful twinkle). Drawn once per tile into the cached bitmap.
- **Rendering:** paper, neighbourhood and stars are baked into cached bitmaps (Canvas). The watercolour plot look (edge pooling, grain, holes, drips) uses a small WebGL shader, or is baked into the bitmap too when the plot changes. Only pins, labels and cards are live HTML.
- **Libraries:** `simplex-noise`, a seeded PRNG (inlined mulberry32/sfc32), `poisson-disk-sampling`, `d3-delaunay` (path graph, also Voronoi for districts). All small, no game engine. See the library check below.
- **Status = classic colours** (the boldest colour on the map): green = healthy, amber = deploying/checking, red = down. Shown as map pins (white disc, coloured ring and icon) plus a red watercolour bloom around anything that is down. Each state also has its own shape (circle / rounded square / diamond) for colour-blind users.
- **Themes:** light (warm paper) and dark (night map, derived from the Maggie Appleton look). Plus a **fun / boring** switch: boring = same layout and data, no ornaments, flat white, plain sans, standard green/red status.
- **Switch UI:** the fun/boring switch is hidden under the theme switch and slides down from beneath it on hover, with an animation. Needs a keyboard/touch path too (focus or tap opens it).
- **Tech:** rough.js for hand-drawn outlines (hedges, building edges), custom pin components (first React Flow nodes, own viewport since 0.6.0), paper texture generated by our own code and baked to bitmaps (no SVG noise filter). All looks come from token sets, so boring mode swaps tokens, not components.


## Rendering techniques

Researched 2026-11-20. Items marked **(from memory)** were not re-fetched.

### Layer stack

1. **World canvas** under the pin layer (this research predates the own viewport: it subscribed to React Flow's transform; now `viewport.subscribe`): paper, neighbourhood, plots. Subscribe to the viewport (`useStore(s => s.transform)` or `onMove`) outside React render, write it to a ref, redraw in rAF with `ctx.setTransform(zoom*dpr, 0, 0, zoom*dpr, x*dpr, y*dpr)`. Don't use React Flow's `<Background>` or `<ViewportPortal>` for this.
2. **Pin layer** (React Flow at the time of this research, now the own viewport) with a transparent background: buildings, pins, labels, selection, drag. Custom nodes `memo`'d; never read the whole `nodes` array in a node. `onlyRenderVisibleElements` only past a few hundred nodes.
3. **Flow canvas** on top: particles drawn from path points sampled once per edge (`getPointAtLength`). SVG `<animateMotion>` is fine under ~50 particles; the canvas handles hundreds.

Upgrade path: if a full-screen shader is ever wanted (weather, live paint), replace layer 1 with a PixiJS or raw WebGL canvas. The layer boundary stays the same.

### Baking tiles

- `OffscreenCanvas` in a module Worker (Chrome, Firefox, Safari 16.4+). Return `transferToImageBitmap()`, or `convertToBlob({ type: 'image/webp' })` for the cache.
- Tiles 512 or 1024 px, one set per zoom bucket. A decoded 1024² tile is ~4 MB, so keep an LRU of loaded tiles and draw only tiles in view. Browser canvas limits are ~16384 px per side (lower on iOS).
- Cache blobs in IndexedDB via `idb-keyval`. Key = `hash(accountSeed, tileXY, zoomBucket, themeId, inputsHash)`; `inputsHash` covers nearby plots, so a tile re-bakes only when something near it changes.
- Keep the draw code to common Canvas 2D calls so it can also run server-side (`@napi-rs/canvas` or `skia-canvas`) if first load is ever too slow. Expect small font and blend differences between Skia and browsers.

### Watercolour plots (Tyler Hobbs' method, from memory)

1. Seeded blob polygon, deformed 30–60 times by recursive midpoint displacement with gaussian jitter, each layer from the shared base shape.
2. Fill each at ~3% alpha with `globalCompositeOperation = 'multiply'`.
3. Pool the interior: a slightly shrunken copy at lower alpha.
4. Darken edges: stroke the outline at low alpha with a 1–2 px blur.
5. Granulation: multiply a seeded value-noise tile at 8–12%.
6. Holes: feathered `destination-out` blobs. Drips: short noise-walked strokes from the border (`perfect-freehand` helps).

About 100 lines of our own code, baked once per plot change. A WebGL shader (domain-warped fbm, SDF edges) is more flexible but harder to debug and cache. `p5.brush` has a watercolour fill but is ~3.5 MB and built around p5: use it as a visual reference only.

Reference: [Tyler Hobbs, "A generative approach to simulating watercolor paints"](https://tylerxhobbs.com/essays/2017/a-generative-approach-to-simulating-watercolor-paints) (URL from memory, open once to confirm).

### Motion

- One rAF loop owns all motion (particles, twinkle, campfire, windows). Clamp `dt` to ~50 ms. Stop the loop when no flows are active and it's daytime.
- Stars twinkle on a separate small canvas at ~10 fps; baked tiles stay static.
- CSS animations for DOM bits (pin pulse, status ring); the Web Animations API for one-off UI motion.
- Pause on `visibilitychange`. Cap ambient effects at 30 fps, 60 fps only during a visible flow, overlay dpr capped at 2.
- `prefers-reduced-motion` (listen for changes): no travelling particles; a flow shows as a steady glow on the path plus a list entry. Single non-looping fades are fine.
- Vizceral's lesson: particle count and speed follow rate, colour follows status. Vizceral itself is no longer maintained; copy the idea, not the library.

### Time scrubber

- Append-only `events(ts, type, entity, edge, payload)` in SQLite, indexed by `ts`, plus status snapshots every N minutes.
- `stateAt(t)` = nearest snapshot + a short fold over events; `flowsActiveAt(t)` feeds the same particle system.
- 7-day replay plays compressed (1 s ≈ 10 min), with flows shown as pulses.

### Postcard export

Compose on canvas: baked tiles for the chosen view, then pins, labels and flows drawn with the same draw functions at 2×, a paper frame and a caption. Labels are drawn, not rasterised from the DOM (`html-to-image` has font and filter quirks). The Playwright container is the server-side path for a scheduled weekly postcard.

### Fonts and sound

- Fraunces (OFL) has variable axes `opsz` 9–144, `wght` 100–900, `SOFT` 0–100 (rounder, cosier labels) and `WONK` 0–1. High `opsz` for big place names, low for small labels. Outfit and JetBrains Mono are also OFL (not re-checked).
- Self-host the woff2 files; the app is VPN-only, so no runtime calls to Google.
- Night sounds: one `AudioContext` created on a user gesture, a looped CC0 file, gain tied to the night value, `ctx.suspend()` when hidden. Candidates: [Night Ambience (freesound 481883, CC0)](https://freesound.org/s/481883), [loopable crickets (OpenGameArt, CC0)](https://opengameart.org/node/130090). Confirm the licence on each page and list every file in `CREDITS`.
